# Expense Tracker

An offline-first personal finance app for Android/iOS built with Expo, React Native and TypeScript. Google Sheets is the remote store; local JSON files are a durable working cache and pending-operation log. There is no application backend or local database.

## Implemented

- Dashboard with current-month totals, search and a virtualized recent-transaction list.
- Add, edit and delete expense/income/transfer transactions. Changes are persisted to the JSON operation queue before the UI reports success and appear immediately in local views/reports.
- Persistent versioned JSON files for transaction cache, pending operations and metadata. Writes use a temporary file, backup copy, and backup recovery if the primary file is missing or invalid.
- Google OAuth authorization-code + PKCE integration, token storage with Expo SecureStore, access-token refresh, and local credential removal/revocation.
- Google Sheets API v4 spreadsheet creation, worksheet initialization/validation, transaction reads, appends and updates. Existing worksheet data is not intentionally overwritten during schema validation; mismatched headers stop the operation with an actionable error.
- Automatic sync attempts on app startup, network restoration and foregrounding, plus transaction-save and manual-sync triggers.
- Stable transaction IDs, remote reconciliation after uncertain create writes, a durable retry queue, bounded exponential retry delay with jitter, partial-failure preservation and basic revision conflict detection.
- Transactions screen with edit/delete actions, reports excluding transfers and tombstones, and CSV export/share.
- GitHub Actions type-check and unit-test workflow.

## Setup: Google OAuth

1. Install Node.js 22 LTS and npm. Run `npm install`, then `npx expo start`.
2. In Google Cloud Console, create a project, enable **Google Sheets API**, configure the OAuth consent screen, and add your Google account as a test user if the app remains in Testing.
3. Create OAuth client IDs for the actual platforms and package identifiers:
   - Android package: `com.zaki1993.expensetracker`. Add the SHA-1 signing certificate fingerprint for the build you install (debug and release fingerprints differ).
   - iOS bundle ID: `com.zaki1993.expensetracker`.
   - A Web OAuth client ID is also useful for Expo web/development tooling. Do not put a client secret in this app.
4. Copy `.env.example` to `.env` and fill in the three public client ID values. The IDs are public identifiers, not secrets. Rebuild the native app after changing environment/configuration values.
5. The Settings screen shows the redirect URI generated by the installed Expo configuration. Confirm the redirect scheme and the platform-specific OAuth client setup in Google Cloud match the installed build and selected Expo AuthSession flow. For a custom development build, register the `expensetracker` scheme and use the appropriate platform OAuth client; Expo Go and standalone builds may use different redirect URIs.
6. Run the app, open Settings, connect Google, then paste an existing spreadsheet ID or create a new spreadsheet. Grant the requested Sheets permission. Only the `https://www.googleapis.com/auth/spreadsheets` scope is requested.
7. Verify with a dedicated test spreadsheet first. Never run destructive testing against your personal finance spreadsheet.

**OAuth is implemented in source but has not been verified end-to-end with real client IDs in this environment.** Exact redirect behavior depends on the Google Cloud OAuth client configuration and the build type; verify the displayed redirect URI on each target device. OAuth consent-screen verification may be required for distribution beyond test users.

## Spreadsheet schema and sync behavior

Tabs: `Transactions`, `Categories`, `Budgets`, and `Settings`. The transaction table uses stable `transaction_id` identifiers. Existing non-empty headers are checked and incompatible headers stop sync instead of being silently replaced.

Each pending operation is written to disk before returning from a save operation. Sync processes operations individually and removes an operation only after a confirmed write or reconciliation with the same transaction ID and update timestamp. If a request fails, the operation remains in the queue and retry metadata is saved. Conflicting remote revisions are preserved locally and surfaced as an error; there is not yet a dedicated conflict-resolution UI. Google Sheets has no transaction-level compare-and-swap primitive, so this is best-effort idempotency rather than a mathematical exactly-once guarantee when other clients edit the same sheet concurrently.

Sync runs while the app is active, on connectivity changes, and when the app resumes. Mobile OSes can suspend apps; the app does not rely on background execution for correctness. Open the app or tap **Sync now** to retry. Authentication/permission failures may require reconnecting the Google account and explicitly retrying.

## Local files and data safety

The app document directory contains:
- `transactions-cache.json`
- `pending-operations.json`
- `sync-metadata.json`

These are versioned JSON files, not SQLite. Writes use a temporary file and a backup file; startup reads the primary file and attempts the backup if the primary is unavailable/invalid. If both copies are invalid, the app throws an error rather than silently returning an empty queue. The JSON data itself is **not encrypted** in this version, although OAuth credentials are stored using SecureStore. Uninstalling the app or clearing app data may destroy unsynchronized transactions. Export/backup first and never clear storage with pending operations.

## Tests and verification

The GitHub Actions workflow runs `npm install`, `npm run typecheck`, `npm run lint` and `npm test`. Unit tests cover money parsing, report aggregation, CSV escaping, durable JSON restart/backup recovery, offline create/edit/delete behavior, and sync behavior (including uncertain-create reconciliation and partial failures).

Not yet verified in this environment: real Google OAuth login/refresh/revocation, reads/writes against a real dedicated test spreadsheet, app restart on physical devices, Android/iOS release builds, native bundle size, startup latency and save latency. Native iOS builds require macOS/Xcode or a configured remote build service. The manual native-build workflow builds an Android Release-variant AAB using the generated development signing configuration and an iOS Release simulator app; neither artifact is a store-ready signed production build. Store distribution requires your own signing credentials. Android builds require the Android SDK; iOS simulator builds run on the GitHub macOS runner.

## Known gaps

- Full category CRUD/archive and budget editing UI are not yet complete, although their sheet schema is reserved.
- Full Bulgarian/English localization, user-selectable light/dark theme, full category CRUD/archive and budget editing UI, and a dedicated conflict-resolution screen remain to be implemented.
- Automatic background sync is best effort only; use foreground/manual sync for dependable progress.
- JSON cache is not encrypted. There is no backend, analytics, ad SDK, or paid service.
- The sync strategy detects common conflicts but cannot guarantee exactly-once writes under concurrent edits because Google Sheets API does not offer atomic conditional row updates.
